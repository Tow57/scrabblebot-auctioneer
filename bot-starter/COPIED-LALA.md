# Copied Lala strategy

Original source: https://github.com/dhruv-1100/lala-scrabblebot/tree/a7433c7b191c30f146f4a4d593ab845d996e50da
Original parameters: `TUNED` / v2.7.5 unchanged; original MIT LICENSE retained at src/copied-lala/LICENSE.

Set `BOT_COPIED_POLICY=lala` to select this candidate. Unset preserves current1.6. Reliable SDK controller, token handling, clock, bid-exposure recovery, serial word ACK+authoritative rack gates, native bootstrap and150ms worker watchdog are retained. No pressure-priority patch is included.

Snapshot adds own bot ID, participants' public balances/scores, closed auction result history and public word-play history. Initial private5 are reconstructed exactly as current own rack minus own purchases plus own consumed letters, validated nonnegative/sum5. Full scoped-subscription readiness, completed-auction count and public timestamp/current-auction guards reject incomplete replay. Snapshot revision includes these public inputs so an opponent update invalidates stale worker decisions.

The original copied engine has no cooperative 95 ms global checkpoint. The worker rejects computed decisions measured beyond 95 ms; the hard 150 ms thread watchdog remains. This is not a hard 95 ms physical interrupt. Revision 02 passed all 78 bot tests and 12 native stress cases (maximum compute 92.8631 ms, response 94.9487 ms, no errors/timeouts). Current no-auction state yields zero/hold instead of fabricating a letter.

Version02 additionally adds optional `act(view, firstWordOnly=false)`: the default original algorithm remains intact, while this adapter enables early return after selecting its first word. It skips later hypothetical words and their bid, which the normal serial client would re-evaluate after the first actual ACK and authoritative rack update. All copied parameters and data remain unchanged. Our client uses only the first copied word, waits for actual ACK+cache and re-evaluates; hypothetical post-word bids are never sent early. EstimatedPrice is accepted by the adapter interface but copied policy retains its own unchanged learned phase-price model.

Version02 parity is limited to the original default outputs and effective normal first action: all12 full-ENABLE native fixture contexts retained the same first word and effective bid. This is not full controller/error-path parity. Version01 also supplied later words in decision.plan, which the controller could reuse if a later worker job failed. Version02 caches only the first selected word; following its consumption, a worker failure can therefore leave fewer fallback cashouts available. Existing spellability, authoritative rack and serialization guards remain. Version01 failed a dense40 native case with a generic worker error at a 135 ms round trip, consistent with the post-compute limit; its failed result is preserved.

Two ten-pair actual-reducer screens used the same fixed seeds (offsets 1700–1709), rotating measured seats and alternating execution order against three frozen v1 policies and two public price-pressure formulas. Revision 02 scored 80.5 points on average versus v1.6's 74.7, mean place 2.8 versus 2.9, and four wins versus two. All ten pairs finished, actions were legal, source pins remained unchanged, and the owned test processes were cleaned up. The second run verifies the performance fix on the same scenarios; it is not independent unseen strength evidence. It does not establish a 2300 rating or superiority to the live leaders. Two-player and first-price strength remain unmeasured. Independent review was by a separate agent of the same model family.
